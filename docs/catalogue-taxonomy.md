# Catalogue taxonomy

Each deployment defines its own collection subject, categories, and tags. New installations have none. The framework does not ship a software catalogue or a fixed category list.

Use one primary category for each card. A library might group cards by subject, while a bookmark collection might group them by topic. Use tags for details that cross category boundaries. These examples describe possible uses and do not create records automatically.

Keep names meaningful to that installation. Changing a category should preserve its database ID and existing card associations. No nested category structure is required by the current collection model.
